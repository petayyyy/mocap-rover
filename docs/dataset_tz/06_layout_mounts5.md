# Промпт 06 — раскладка камер на пяти точках крепления: мир, покрытие, датасет, приёмка

Прочитай `docs/dataset_tz/README.md`, `docs/camera_mounting.md` и
`docs/camera_mounting.svg` (схема для конструктора), `scripts/generate_world.py`
(функции `layout_rotation`, `layout_angles`, цикл размещения камер и
геометрическая проверка покрытия), `scripts/set_world_rates.py`,
`scripts/record_dataset.py`, `docs/shared_rover_tracking.md`.

## Почему

Точки крепления на потолке фиксированы отверстиями: четыре угловых
(3, 3), (9, 3), (3, 9), (9, 9) и одно центральное (6, 6), на котором стоят
две камеры не дальше 0.60 м друг от друга (минимума нет), лидар Airy
там же, на 2.75 м.
Раскладка из репозитория (три ряда по y = 2, 6, 10) на этих точках
невозможна. По геометрии линзы (равноугольная, 160° по диагонали,
отсечка 80°, гейт падения 65°) дирижёр получил для пяти точек:
видимость маркера хотя бы одной камерой 99.4 % площади, двумя — 69 %
(в репозиторной раскладке 100 / 91 %); наклон угловых камер к центру
только ухудшает (10° → 97 %, 15° → 95.6 %). Лучший вариант: все шесть
камер в надир, угловые длинной стороной вдоль X, центральная пара
(5.85, 6) вдоль X и (6.15, 6) вдоль Y. Это надо подтвердить рендером и
трактом, включая заслонение корпусом лидара между центральными камерами.

## Что сделать

1. **Генератор.** В `scripts/generate_world.py` добавить `--layout mounts5`
   и, только для него, свои позиции камер (`(3,3) (9,3) (3,9) (9,9)
   (6−s/2,6) (6+s/2,6)`, где `s` = разнос центральной пары, по умолчанию
   0.30 м (покрытие от `s` в пределах 0…0.6 м не зависит: проверено
   дирижёром геометрически, 99.4 / 69 % при любом `s`)) и углы: все `tilt = 0`, `roll = 0` у camera_1…5,
   `roll = 90°` у camera_6. Существующие раскладки `nadir` и `final`
   должны генерировать байт-в-байт прежние миры (тест: пересобрать
   `mocap_arena_imx219` и сравнить `diff`). Параметр
   `--layout-variant` для перебора: `corner_tilt_deg` (0/10),
   `corner_roll_deg` (0/90), `centre` (`xy` — перпендикулярные длинные
   стороны; `xx` — обе вдоль X; `tilt_out_15` — обе наклонены на 15° от
   друг друга вдоль X). Лидар Airy при `--lidar airy` остаётся в
   (6, 6, 2.75) с корпусом-мешем, как сейчас.
2. **Мир.** `generate_world.py --profile imx219_160 --layout mounts5 --lidar
   airy --ideal-cameras --world-name mocap_arena_mounts5`, затем
   `set_world_rates.py ... --camera-hz 80 --truth-hz 200 --lidar-hz 10
   --max-linear 12`, `gz sdf -k` даёт `Valid.`; пути к мешам лидара в
   SDF — относительные к `GZ_SIM_RESOURCE_PATH`, а не абсолютные
   (сейчас в SDF лежит `/home/popka/...`; исправить в генераторе для
   всех раскладок, это заодно чинит запуск на любой машине).
   Калибровка для рантайма — `config/mocap_arena_mounts5/runtime_cameras.json`.
3. **Геометрическое покрытие.** Вывод генератора расширить: кроме
   «непокрытых точек» печатать долю площади, видимую ≥ 1 / ≥ 2 / ≥ 3
   камерами при гейте падения 65° и отступе 8 px от края, для высот
   0.3654 (маркер) и 0.483 (верх соперника). Таблица для базового
   варианта и трёх альтернатив из п. 1 — в отчёт. Ожидание: базовый
   ≈ 99.4 / 69 % на маркере.
4. **Рендер и заслонение.** Запустить мир (с разрешения пользователя, свой
   `GZ_PARTITION`), снять по кадру с каждой камеры (`scripts/check_sim.py`),
   приложить кадры центральных камер: виден ли корпус лидара, какую
   долю кадра он закрывает (маска по цвету/яркости корпуса, в процентах
   площади и в градусах от оси). Проверить, что лидар не видит корпуса
   камер: в скане нет возвратов ближе 0.5 м от сенсора.
5. **Датасеты на новой раскладке.** Как в `handoff_worker.md`, шаг 1:
   `dataset_mounts5_background` (3 с пустой арены) и `dataset_mounts5_01`
   (40 с, `drive_random --seconds 1200 --speed 5 --seed 7`). Проверка
   `conductor_check.py truth` и `check_dataset.py --frames 40 --scans 4`.
   Фон лидара по лучам и пол — из нового фона.
6. **Приёмка тракта.** Штатная команда реплея (с фонами новой раскладки)
   на `dataset_mounts5_01`; для сравнения — та же команда на
   `dataset_imx219_03`. Дополнительно `--cameras camera_1,camera_2,camera_3,camera_4`
   (без центральной пары) и `--no-lidar`. Разбор ошибки по зонам: центр
   (обе координаты 3…9), борта, углы (обе координаты < 2 или > 10) —
   потому что двойное покрытие есть только в центре.

## Критерии приёмки

| Метрика | Порог |
|---|---|
| tag_rover на `mounts5_01` | P50 ≤ 0.06 м, P95 ≤ 0.15 м, valid ≥ 98 %, yaw P95 ≤ 5°, подмен 0 |
| opponent на `mounts5_01` | P50 ≤ 0.06 м, P95 ≤ 0.15 м, valid ≥ 98 %, подмен 0 |
| ухудшение против датасета 03 в репозиторной раскладке | названо по зонам с числами; в центре не хуже чем на 10 % |
| без центральной пары | valid ≥ 90 %, подмен 0 |
| геометрия | таблица покрытия базового и трёх альтернатив; заслонение лидаром измерено |
| генератор | прежние раскладки байт-в-байт; тесты зелёные |

## Запрещено

Менять оценщик, `record_dataset.py`, `check_dataset.py`, файлы дирижёра,
принятый тракт (кроме путей к фонам через флаги). Двигать точки крепления
или лидар. Подгонять параметры тракта под новую раскладку без чисел
до/после на обоих датасетах.

Отчёт по шаблону README на `mounts5_01` и 03, таблица покрытия, кадры
