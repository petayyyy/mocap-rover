# Стартовое сообщение для рабочего чата на ноутбуке (Intel iGPU)

Скопировать целиком в новый чат Claude Code, открытый в клоне репозитория
на ноутбуке. Дальше рабочий чат получает промпты `01..04` по одному от
чата-дирижёра.

---

Ты — исполнитель в проекте `mocap-rover`: локализация двух боевых роверов по
шести потолочным камерам и лидару. Работа идёт по ТЗ из каталога
`docs/dataset_tz/`. Дирижёр — отдельный чат; он выдаёт промпты по одному,
проверяет отчёты независимым прогоном и решает, что принято. Ты не
переходишь к следующему промпту без его «принято».

Сначала прочитай полностью, ничего не пропуская:
`docs/dataset_tz/README.md`, `docs/dataset_tz/setup_other_pc.md`,
`docs/hybrid_rover_tracking.md`, `readme.md`.

Эта машина: Intel Core Ultra 7 155H со встроенной графикой, Ubuntu 24.04,
без NVIDIA. Всё, что связано с CUDA, `cv2.cuda`, torch на GPU, `device=0`,
здесь не запускать и не проектировать под GPU; общий тракт должен работать
на CPU, GPU-ускорение будет отдельным шагом на другой машине. Абсолютные
пороги по миллисекундам из README заданы для RTX 3070 и на этой машине не
являются критерием приёмки; критериями остаются точность, доля valid,
отсутствие подмен идентичности и зелёные тесты.

## Шаг 0. Окружение и проверка

Выполни разделы 1–3 методички `docs/dataset_tz/setup_other_pc.md`.
Ожидаемые результаты: `gz sim --version` даёт 8.x, тесты
`source /opt/ros/jazzy/setup.bash && .venv/bin/python -m unittest discover -s tests -q`
дают `Ran 255 tests ... OK`, `gz sdf -k` на пересобранном мире даёт `Valid.`.
Если что-то из этого не так, остановись и отчитайся, не чини молча.

## Шаг 1. Записать датасеты здесь (готовые не переносятся)

Всё в отдельном разделе транспорта `GZ_PARTITION=imx219lap`, сервер без GUI:
`gz sim -s -r --headless-rendering worlds/mocap_arena_imx219.sdf` с
`GZ_SIM_RESOURCE_PATH="$PWD/models:$PWD"`. Перед каждой записью убедись
через `pgrep -af "gz sim|drive_|record_dataset"`, что от прошлой ничего не
осталось: два драйвера на одном `cmd_vel` уже один раз испортили запись.

Записать три каталога в `artifacts/`:

1. `dataset_imx219_01_background` — пустая арена, 3 сим-секунды. Мир без
   роверов делается функцией `empty_world` из `scripts/record_lidar_background.py`
   (копия мира с удалёнными нестатическими моделями), сервер поднимается на
   этой копии. `truth.jsonl` будет пустым, это нормально.
2. `dataset_imx219_01` — 40 сим-секунд, оба ровера,
   `scripts/drive_random.py --seconds 1200 --speed 5 --seed 7`, запись
   `scripts/record_dataset.py --config config/mocap_arena_imx219/runtime_cameras.json --output artifacts/dataset_imx219_01 --seconds 40`.
   Драйвер запускать за 30–45 с до рекордера, чтобы роверы уже ехали.
3. `dataset_imx219_02` — 40 сим-секунд длинных прямых:
   `scripts/drive_sprints.py --seconds 1200 --speed 5 --brake 3 --stuck-s 20`.
   Этот драйвер на RTX-машине давал перевороты; поэтому после записи
   обязательна проверка ниже, и если она не проходит, датасет удаляется и
   пишется заново с `--speed 4`. Не тратить на это больше двух попыток —
   тогда оставить только 01 и сказать об этом дирижёру.

Физика мира не пускает ровер выше ~6 м/с (колёса по одометрии крутятся на
11, корпус буксует), поэтому 5 м/с — рабочий режим, за 11 м/с не гнаться.

Проверка каждого датасета, результат целиком в отчёт:

- `meta.json`: по камерам ~3335 кадров за 40 с (83.7 fps × 40),
  `image_size_errors: 0`, ~400 сканов лидара, ~16000 строк эталона;
- по `truth.jsonl`: доля строк с `z > 0.2` у каждого ровера ≤ 2 %, скачков
  XY больше 0.4 м между соседними строками нет, максимум скорости и P90
  скорости у каждого ровера (ожидается до ~5 м/с);
- `scripts/check_dataset.py <каталог> --frames 40 --scans 4`: на камерах с
  принятыми наблюдениями `xy_error_p50_m` около 0.02 и `yaw_error_p95_deg`
  меньше 2; в `check_report.json` есть точки лидара около обоих роверов.

На этой машине RTF будет 0.02–0.05, то есть 40 сим-секунд пишутся 15–35
минут; это ожидаемо, не прерывать. После записей проверить, что процессы
Gazebo завершены.

## Шаг 2. Отчёт дирижёру

По шаблону из README, плюс таблица по датасетам с числами из проверки выше.
После этого жди промпт `01_replay.md` от дирижёра. Промпты `01..04` лежат в
`docs/dataset_tz/`, но выполняются строго по одному и только по команде.

## Правила, которые не обсуждаются

- Никакого обучения на роверах: YOLO и любые обученные детекторы объектов
  запрещены; разрешены модель фона по клипу пустой арены, стартовый
  прямоугольник соперника, декодирование маркера, кластеризация лидара,
  классические трекеры.
- Рантайм не читает эталон. Датасеты, оценщик `scripts/evaluate_recording.py`,
  `scripts/record_dataset.py`, `scripts/generate_world.py`, `scripts/check_dataset.py`
  и `config/mocap_arena_imx219/` не меняются.
- Один тракт для обоих роверов: «прогноз → окно → измерение → IMM-фильтр»,
  маркер — надстройка идентичности.
- Каждая итерация заканчивается реплеем на полном датасете, оценкой и
  отчётом. Тесты зелёные. Коммиты небольшие, с понятными сообщениями,
  датасеты в git не попадают (`artifacts/` в `.gitignore`).
- Честность отчёта важнее результата: что не прошло и почему — с числами.
