# ТЗ для исполнителя: детекция двух роверов по датасету IMX219

Этот каталог — набор промптов для отдельного чата-исполнителя. Он идёт строго по
ТЗ, переписывает и тестирует код по датасету, пока не добьётся стабильного
определения обоих роверов с минимальной задержкой. Чат-дирижёр (тот, где
написаны эти файлы) проверяет отчёты независимым прогоном и выдаёт следующий
промпт. Исполнитель не меняет датасет, эталон и оценщик.

Порядок промптов: `01_replay.md` → `02_tag_rover.md` → `03_opponent.md` →
`04_shared_latency.md`. Каждый следующий начинается только после того, как
дирижёр принял предыдущий.

## Что зафиксировано

- Мир: `worlds/mocap_arena_imx219.sdf`, сгенерирован
  `scripts/generate_world.py --profile imx219_160 --layout final --lidar airy
  --ideal-cameras --world-name mocap_arena_imx219`, затем
  `scripts/set_world_rates.py ... --camera-hz 80 --truth-hz 200 --lidar-hz 10 --max-linear 12`.
- Камеры: 6 × Waveshare IMX219-160, режим 1640×1232, 80 fps, идеальный
  эквидистантный fisheye (160° по диагонали, f = 734.5 px, отсечка 80°),
  `distortion_model: fisheye`, D = 0. Раскладка: угловые камеры (y = 2 и y = 10)
  наклонены на 10° к центральной линии арены, длинная сторона кадра вдоль X;
  средние камеры (y = 6) смотрят в надир, длинная сторона вдоль Y.
- Лидар: RoboSense Airy в (6, 6, 2.75), смотрит вниз, 10 Гц, 900 × 95 лучей,
  топик `/robosense_airy/normal/scan`.
- Роверы: `tag_rover` 0.72×0.52 м с AprilTag 36h11 ID 0 сверху и ID 1 снизу,
  маркер 0.4 м на высоте 0.3654 м; `yolo_rover` (в эталоне `opponent`)
  0.9×0.52 м, высота верха 0.483 м, без меток. Скорость до 11 м/с.
- Калибровка для рантайма: `config/mocap_arena_imx219/runtime_cameras.json`
  (роль `image_calibrated`, камеры идеальные, лидар включён).

## Датасеты

| Каталог | Что внутри |
|---|---|
| `artifacts/dataset_imx219_01/` | 40 сим-с, случайные точки (`drive_random.py --speed 11 --seed 7`); фактически до 5.7 м/с, P90 ≈ 3.8 м/с; много поворотов и сближений |
| `artifacts/dataset_imx219_02/` | **Брак, не использовать для приёмки.** 40 сим-с спринтов (`drive_sprints.py --speed 5`), но tag_rover половину записи лежит перевёрнутым (z > 0.2 м в 51 % строк эталона) и виден только нижний маркер ID 1. Годится лишь как тест переворота. Будет перезаписан |
| `artifacts/dataset_imx219_01_background/` | 3 сим-с пустой арены (те же камеры и лидар), для модели фона; `truth.jsonl` пустой |

Физика мира ограничивает ровер примерно 6 м/с: по одометрии колёса
крутятся на 11 м/с, корпус буксует. Поэтому текущие датасеты покрывают
режим до 5 м/с; критерии по задержке при этом не смягчаются, потому что они
заданы в миллисекундах, а не в метрах. В `truth.jsonl` возможны короткие
эпизоды, когда драйвер ставит перевёрнутый ровер на колёса (z поднимается до
0.3 м и возвращается к 0.14); их видно по `z`, XY при этом не прыгает.

Проверка дирижёра (`scripts/check_dataset.py`, отчёт в
`check_report.json` внутри датасета): на принятых наблюдениях маркера ошибка
XY 2 см и yaw < 1°, то есть калибровка, геометрия мира и метки времени
согласованы. Известная стартовая точка для исполнителя: гейт `base_height`
отбрасывает большинство fisheye-детекций (PnP-глубина на fisheye плохая, а
ray-XY хороший), полный кадр 1640×1232 на CPU стоит 27–36 мс, декодирование
FFV1 4–5 мс на кадр (в бюджет обработки не входит).

Формат описан в `scripts/record_dataset.py`:

| Файл | Содержимое |
|---|---|
| `camera_N.mkv` | FFV1 без потерь, RGB, 1640×1232 |
| `camera_N.jsonl` | по строке на кадр: `index`, `stamp_ns` (сим-время рендера), `wall_ns` |
| `lidar/scan_NNNNNN.npz` | `ranges` float32 (95×900), `azimuth` (900), `elevation` (95), `range_min`, `range_max` |
| `lidar.jsonl` | `file`, `stamp_ns`, `wall_ns` |
| `truth.jsonl` | PosePublisher 200 Гц: `object_id` (`tag_rover`/`opponent`), `stamp_ns`, `x`, `y`, `z`, `yaw` |
| `clock.jsonl` | сим-часы раз в 100 мс |
| `runtime_cameras.json` | калибровка для рантайма |
| `meta.json` | счётчики кадров, сканов, дропов |

Декодировать видео можно `cv2.VideoCapture` или `ffmpeg -i camera_1.mkv -f rawvideo -pix_fmt rgb24 -`.
Кадр `index` соответствует строке `index` в jsonl.

Ограничения датасета, которые нужно помнить: Gazebo не моделирует смаз,
rolling shutter и шум сенсора. Точность на нём оптимистична; архитектура
обязана оставлять место для поправки времени по строке кадра и для короткой
экспозиции (см. `docs/hybrid_rover_tracking.md` и ответы дирижёра).

## Жёсткие правила для исполнителя

1. Никакого обучения на роверах: YOLO и любые обученные детекторы объектов
   запрещены. Разрешены: модель фона по клипу пустой арены, стартовый
   прямоугольник соперника в первом кадре (см. `03_opponent.md`), декодирование
   маркера, кластеризация лидара, классические трекеры (KLT, корреляционные).
2. Рантайм не читает `truth.jsonl` и `cameras_ground_truth.json`. Эталон
   использует только оценщик и, единственный раз, инициализация прямоугольника
   соперника в реплее.
3. Не менять: датасет, `scripts/evaluate_recording.py`, `scripts/record_dataset.py`,
   `scripts/generate_world.py`, файлы в `config/mocap_arena_imx219/`.
4. Выход реплея совместим с `scripts/evaluate_recording.py`: каталог с
   `odometry.jsonl` и `observations.jsonl` в формате `scripts/run_localization.py`.
5. Общий код для обоих роверов: один тракт «прогноз → окно → измерение →
   IMM-фильтр», маркер это надстройка идентичности, а не отдельный конвейер.
6. Каждая итерация: изменение → реплей на полном датасете → оценка → отчёт по
   шаблону ниже. Без отчёта работа не считается сделанной.
7. Тесты: `/usr/bin/python3 -m unittest discover -s tests -q` зелёные после
   каждой итерации. Новые модули получают свои тесты.

## Критерии приёмки (общие)

Все проверяются дирижёром независимым запуском реплея и оценщика.

| Метрика | Порог |
|---|---|
| XY ошибка P95, каждый ровер, по всем `valid` выходам | ≤ 0.15 м |
| XY ошибка P50 | ≤ 0.06 м |
| Доля сим-времени с `valid` треком, каждый ровер | ≥ 98 % |
| Подмена идентичности (трек `tag_rover` на позиции соперника > 0.5 м дольше 100 мс) | 0 |
| Обработка одного кадра камеры, P95, при параллельной работе 6 камер | ≤ 5 мс |
| Пропускная способность реплея | ≥ 1.0 × сим-времени (480 кадров/с суммарно) |
| Возраст последнего измерения на выходе, P95 | ≤ 25 мс сим-времени |
| Yaw `tag_rover` P95 | ≤ 5° |

## Шаблон отчёта исполнителя

```
## Итерация N — <одна строка: что изменено>
Команды: <реплей>, <оценка>
Коммит/диф: <hash или список файлов>
tag_rover: P50 __ м, P95 __ м, valid __ %, yaw P95 __°, swaps __
opponent:  P50 __ м, P95 __ м, valid __ %, swaps __
Обработка кадра: mean __ мс, P95 __ мс; реплей __ × сим-времени; возраст измерения P95 __ мс
Тесты: __ passed
Что не прошло и почему (честно): ...
Следующий шаг: ...
```

Дирижёр отвечает: «принято, следующий промпт» или списком конкретных
расхождений с его собственным прогоном.
