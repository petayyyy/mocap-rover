# Промпт 08 — SAM2 как второе мнение для соперника: касания, перезахват, GPU

Прочитай `docs/dataset_tz/README.md`, `docs/shared_rover_tracking.md`,
`docs/dataset_tz/setup_other_pc.md`, `localization_contracts/opponent_camera.py`,
`localization_contracts/foreground.py` (`SilhouetteObserver.measure`),
`localization_contracts/camera_worker.py` (`process_opponent`, `opponent_stream`),
`scripts/replay_dataset.py` (флаги `--opponent-stream`, `--opponent-stream-stagger`,
`--tag-max-cameras`, оператор `operator_box_from_truth`).

## Зачем

Соперник ищется вычитанием фона + силуэтом + лидаром. Слабые места этого
пути: роверы касаются и их силуэты сливаются в одно пятно (риск подмены),
тени и смена света, соперник долго стоит и модель фона его «впитывает»,
перезахват после потери возможен только по оператору. SAM2 ведёт объект по
видео от одного прямоугольника и не зависит от фона. Задача — добавить его
**вторым мнением**, не ломая основной путь, и измерить, что он даёт и
сколько стоит на GPU.

## Что разрешено и что нет

- Разрешены **готовые** модели общего назначения без дообучения: SAM2 / SAM2.1
  (`facebookresearch/sam2`), при нехватке скорости — облегчённые аналоги с
  той же идеей (EfficientTAM, EdgeTAM, SAMURAI как надстройка над SAM2).
  Любое обучение или дообучение на роверах, арене, кадрах датасетов — запрещено,
  как и раньше (README, правило 1).
- Подсказки модели — только из рантайма: прямоугольник оператора (как сейчас,
  единственное чтение эталона) и прогноз фильтра. Эталон рантайм не читает.
- Основной путь (фон + силуэт + лидар) не менять. SAM2 — отдельный источник
  измерений со своей погрешностью.
- Импорт `torch`/`sam2` ленивый: без них весь пакет и все тесты работают как
  сейчас, SAM2-тесты пропускаются (`skipUnless`).

## Машина

Нужна NVIDIA GPU. В отчёт: модель GPU, VRAM, драйвер, CUDA, версии torch и
sam2, CPU. Установка — в `.venv`, системные драйверы не трогать:

```bash
.venv/bin/python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
```

```bash
.venv/bin/python -m pip install "git+https://github.com/facebookresearch/sam2.git"
```

Веса (начать с самой лёгкой): `sam2.1_hiera_tiny.pt`, при необходимости
`sam2.1_hiera_small.pt`, из ссылок в README репозитория sam2; положить в
`models/sam2/` (в git не коммитить, путь — флагом `--sam2-checkpoint`).

Датасеты не перезаписывать; скопировать с основной машины (каталоги
`artifacts/` в git нет): `dataset_mounts5b_01`, `dataset_mounts5b_background`,
`dataset_imx219_03`, `dataset_imx219_01_background`.

## Что сделать

1. **Датасет касаний.** Новый `scripts/drive_encounters.py` (старые драйверы не
   менять): `tag_rover` едет по случайным точкам, `yolo_rover` преследует его и
   доводит до контакта (бортом, лоб в лоб, толкание 1–3 с), затем отъезжает;
   не меньше 8 контактов за 40 с, скорость до 3 м/с. Записать
   `dataset_mounts5b_contact_01` в мире `mocap_arena_mounts5b` по рецепту
   `handoff_worker.md`, шаг 1 (свой `GZ_PARTITION`). Проверка
   `conductor_check.py truth` и `check_dataset.py --frames 40 --scans 4`;
   в отчёт — число эпизодов с расстоянием между центрами < 0.8 м и их суммарная
   длительность. Перевороты и клинчи драйвера — как в журнале дирижёра: если
   запись бракованная, перезаписать с другим seed и указать какой.
2. **Обёртка SAM2.** `localization_contracts/sam2_opponent.py`:
   - видео-предиктор SAM2 на камеру, вход — кадр соперника (поток 640×480,
     как в гибриде, `--opponent-stream 640x480@30`), выход — бинарная маска
     в координатах этого кадра и оценка уверенности;
   - старт от прямоугольника оператора на камерах, где он есть;
   - повторная подсказка прямоугольником из прогноза фильтра (проекция
     габарита соперника в кадр), когда уверенность ниже порога, маска
     пустая/развалилась или трек соперника `LOST`; при подсказке память
     предиктора сбрасывается;
   - память ограничена (окно последних кадров), чтобы время и VRAM не росли
     со временем записи.
3. **Включение в тракт.** Маска SAM2 идёт в тот же `SilhouetteObserver.measure`
   (окно = весь малый кадр или окно вокруг прогноза), получается обычное
   наблюдение соперника с `source="sam2"` и своей σ (подобрать на
   `mounts5b_01`, зафиксировать, не трогать на остальных датасетах).
   Флаги реплея:
   - `--sam2-mode off|backup|always` (по умолчанию `off`);
   - `--sam2-max-cameras N` (по умолчанию 2: ближайшие к прогнозу соперника);
   - `--sam2-hz` (по умолчанию 15), `--sam2-checkpoint`, `--sam2-config`;
   - `--sam2-latency-ms` — задержка результата в сим-времени, чтобы реплей
     оставался детерминированным; по умолчанию — измеренный тобой P95 на этой
     GPU. Настоящие времена GPU пишутся в `timing.json` отдельно
     (`sam2_ms` P50/P95/max, VRAM пик).
   `backup`: SAM2 считается всегда (держит память), но его измерение подаётся в
   фильтр только когда основной путь ненадёжен — роверы ближе
   `--identity-close-m`, силуэт отвергнут или отсутствует дольше 100 мс,
   трек `LOST`. `always`: подаётся всегда.
4. **Защита идентичности.** Измерение SAM2 отвергается (со счётчиком причины
   в `observations.jsonl`), если центр маски дальше гейта от прогноза соперника,
   ближе к прогнозу `tag_rover`, чем к прогнозу соперника, или маска
   перекрывает прямоугольник маркера `tag_rover` больше чем на 30 %. При
   отказе — повторная подсказка на следующем кадре SAM2.
5. **Перезахват без оператора.** Флаг реплея `--opponent-blackout S:E[,S:E]`
   (сим-секунды): в эти интервалы кадры соперника для основного пути и SAM2
   заменяются пустой ареной из фона (имитация полного заслонения/сбоя), лидар
   тоже не даёт соперника. После окончания интервала оператор не помогает.
   Метрика: время от конца интервала до первого `valid` выхода соперника
   с ошибкой < 0.15 м, и было ли это измерение от SAM2 или от фона/лидара.
6. **Эксперимент.** База — гибрид из `replay_10`
   (`--link-emulation cm4 --roi-max-px 320 --roi-jpeg-max-px 320 --no-opponent-jpeg
   --tag-max-cameras 3 --opponent-stream 640x480@30 --opponent-stream-stagger
   --acquire-full-frame-hz 10`, остальное как в журнале дирижёра). Матрица на
   `mounts5b_01`, `imx219_03`, `mounts5b_contact_01`:
   - база (`--sam2-mode off`);
   - `--sam2-mode backup`;
   - `--sam2-mode always`;
   - `backup` и `--no-lidar` (только камеры);
   - `backup` при `--sam2-max-cameras 1` и `--sam2-hz 10` (дешёвый вариант);
   - на `mounts5b_01`: база и `backup` с `--opponent-blackout 12:14,28:30`.
   Для каждого: оба ровера P50/P95, valid, подмены (`conductor_check.py replay`),
   возраст P95, доля измерений соперника от SAM2, отказы SAM2 по причинам,
   время перезахвата, `sam2_ms` P50/P95, VRAM.
7. **Скорость на GPU отдельно.** `scripts/bench_sam2.py`: один и N камер
   (1, 2, 3, 6) по 640×480, 30 с, tiny и small, fp16/bf16. Таблица: кадров/с,
   P50/P95 мс, VRAM, загрузка GPU. Ответить: сколько камер × Гц тянет эта GPU
   с запасом 30 %.

## Критерии приёмки

| Метрика | Порог |
|---|---|
| Подмены на `mounts5b_contact_01`, `backup` | 0 (база — сколько есть, в отчёт) |
| Соперник на `mounts5b_01` и `imx219_03`, `backup` против базы | P95 не хуже +5 %, valid не ниже базы |
| `tag_rover` | без изменений (P95 ±2 %, valid, yaw) |
| Перезахват после 2 с заслонения, `backup` | `valid` с ошибкой < 0.15 м не позже 0.5 с после конца интервала, без оператора |
| GPU, выбранный вариант | `sam2_ms` P95 ≤ 40 мс при выбранном числе камер × Гц, загрузка GPU ≤ 70 % |
| Тесты | зелёные с torch и без него; новые модули — со своими тестами |

Если `backup` не даёт выигрыша на касаниях — это тоже результат: назвать
числа и причину (например, SAM2 сам перескакивает на соседний ровер),
пороги не подгонять.
