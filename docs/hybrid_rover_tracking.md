# Комбинированное сопровождение ровера

> Замещён `docs/shared_rover_tracking.md` (промпт 04).

Цель — не требовать видимой метки в каждом кадре. Метка ArUco/AprilTag создаёт
трек и подтверждает личность. После этого L2 и камеры могут продолжать только
этот уже подтверждённый трек.

## Поток данных

1. **ArUco/AprilTag:** начальная `(x, y)`, ID и периодическая коррекция дрейфа.
2. **Прогноз:** фильтр постоянной скорости приводит состояние к timestamp
   очередного измерения. Используется время экспозиции/скана, не время доставки.
3. **3D-лидар:** удаляются пол и точки выше ровера, затем в динамическом окне
   прогноза ищется связный ровероподобный кластер. Это основной источник
   метрической позиции при невидимой метке.
4. **Камера без метки:** MOG2 работает только для неподвижных потолочных камер и
   только внутри ROI, спроецированного из прогноза. Bounding box переводится в
   метры через `cuboid.localize_box`. Это резерв между сканами лидара.
5. **Слияние:** каждое измерение проходит innovation gate. После потери трека
   лидар и MOG2 не имеют права создать новый — требуется метка, иначе возможна
   подмена ровером соперника.

Реализация находится в `localization_contracts/hybrid_rover.py`:

- `HybridRoverTracker` — фильтр, временные окна, защита личности;
- `LidarRoverDetector` — crop, кластеризация и выбор по прогнозу;
- `StaticVoxelBackground` — фон пустой арены для удаления стен и конструкций;
- `CameraMotionFollower` — удаление фона в предсказанном ROI;
- `project_world_to_image` — проекция прогноза в ROI конкретной камеры;
- `scan_grid_to_points` — перевод организованного scan в XYZ;
- `lidar_gate_radius` — окно с учётом скорости и периода L2.

## Параметры для 40 км/ч

`40 км/ч = 11.11 м/с`. При 90 FPS смещение равно 12.3 см/кадр, а при текущих
5.55 Гц L2 — около 2.0 м/скан. Поэтому текущий L2 нельзя использовать как
единственный источник.

Рекомендуемый режим:

| Параметр | Значение |
|---|---:|
| Камеры | 640×480, 90 FPS |
| Экспозиция | 0.5–1.0 мс, яркий постоянный свет |
| Публикация фильтра | 100 Гц |
| Coast без измерения | 240 мс максимум |
| Шум ускорения фильтра | 30 м/с² — допускает быстрый поворот на маленькой арене |
| L2 | 5.55 Гц допустимо только вместе с камерами; желательно 20+ Гц или обработка точек с индивидуальными timestamp |
| Синхронизация часов | ошибка не более 1 мс, поскольку 10 мс дают 11 см ошибки |
| Маркер | нужен при старте, после `lost` и периодически для контроля ID/дрейфа |

MOG2 не годится для глобальной детекции: тени, люди и второй ровер тоже являются
foreground, а остановившийся объект постепенно становится фоном. Поэтому он
используется только как слабое продолжение подтверждённого трека. Если ровер
может долго стоять без видимой метки, удержание обеспечивает лидар.

## Подключение к текущему тракту

Для каждого изображения сначала вызвать обычный детектор метки. Его метрическую
позицию передать как `source="marker"`. Если метки нет, спроецировать прогноз в
кадр, вызвать `CameraMotionFollower.update`, локализовать полученный bbox через
`cuboid.localize_box` и передать как `source="camera_motion"` с дисперсией не
меньше `0.04 м²`.

Для L2 преобразовать scan в мировые XYZ, взять прогноз на timestamp скана,
удалить заранее записанный фон пустой арены через `StaticVoxelBackground`,
вычислить `lidar_gate_radius`, вызвать `LidarRoverDetector.detect` и передать
центр кластера как `source="lidar"`. Публиковать `predict(now)` отдельно с
частотой 100 Гц; `mode="coasting"` означает прогноз без свежего измерения,
`mode="lost"` запрещает использовать позицию для управления.
