# Как самому запустить скоростной заезд с GUI

Три терминала и браузер. Всё из корня репозитория
`/home/popka/Drone/mocap-rover`.

## Шаг 0. Подготовить «быстрый» мир (один раз)

Мир из репозитория ограничивает ровер **1 м/с** в плагине DiffDrive, поэтому
без этого шага скоростного заезда не будет вовсе. Заодно поднимаются частоты
камер и публикации истины и рядом пишется калибровка **именно для этого
мира** — штатные `config/*.json` рантайм не примет.

```bash
python3 scripts/set_world_rates.py worlds/mocap_arena_l2.sdf \
  --camera-hz 30 --truth-hz 200 --max-linear 12 \
  --output /tmp/arena_fast.sdf --export-config /tmp/arena_fast_cameras.json
```

`--camera-hz 30` выбран для GUI: при 90 Гц шесть камер дают 540 кадров/с
рендера, и вместе с окном Gazebo картинка станет рваной. Для замеров без GUI
ставьте 90.

## Шаг 1. Терминал 1 — Gazebo с окном

```bash
MOCAP_WORLD=/tmp/arena_fast.sdf scripts/run.sh
```

Откроется окно арены. Дайте ему секунд 20 на прогрузку.

## Шаг 2. Терминал 2 — локализация

```bash
source /opt/ros/jazzy/setup.bash
.venv/bin/python scripts/run_localization.py \
  --config /tmp/arena_fast_cameras.json --tag-only \
  --clock-topic /world/mocap_arena/clock --port 8081 \
  --output /tmp/live_$(date +%H%M%S)
```

Дождитесь строки `live runtime ready; http://127.0.0.1:8081`.

## Шаг 3. Браузер

Откройте **http://127.0.0.1:8081** — 3D-сцена, точки лидара, числа,
превью шести камер.

- тянуть мышью — поворот, колесо — зум, правая кнопка — сдвиг;
- галочка **«следовать за ровером»** — камера едет за ним, на скорости это
  единственный удобный режим;
- панель слева вверху: состояние, X/Y, курс, **скорость в км/ч**, σ, возраст
  измерения, частота выхода, сколько точек дал лидар.

## Шаг 4. Терминал 3 — руль

```bash
source /opt/ros/jazzy/setup.bash
.venv/bin/python scripts/teleop_tag_rover.py --linear 11.11
```

| клавиша | действие |
|---|---|
| `W` / `S` | газ вперёд / назад |
| `A` / `D` | поворот |
| `Пробел` | притормозить |
| `X` | стоп |
| `1`…`9` | верхний предел 1…9 м/с |
| `0` | 12 м/с (43 км/ч) |
| `R` | вернуть ровер на «домой» и на колёса |
| `T` | поставить на колёса на месте |
| `C` | сбросить пики |
| `Q` | выход |

Дом задаётся флагом: `--home X Y YAW_DEG` (по умолчанию `3 2 0`).

Строка «положение» показывает `z` и одно из: *на колёсах*, *на боку*,
**ПЕРЕВЁРНУТ — виден нижний маркер**. Признак берётся из кватерниона
симулятора: если собственная ось Z ровера смотрит вниз, он на спине.

Сброс — это телепорт, поэтому фильтр отклоняет его по гейту физической
скорости и трек уходит в `REACQUIRING`, пока метка не подтвердит личность
заново. Так и задумано: прыжок на четыре метра за кадр не бывает
настоящим движением.

Клавишу надо **держать**: отпускание в терминале не видно, поэтому тяга
плавно затухает за ~0.25 с после того, как автоповтор прекратился.

В панели консоли одновременно видно:

```
СИМУЛЯТОР   x=  6.214  y=  5.880  yaw=  +44.9°    7.02 м/с =  25.3 км/ч
ЛОКАЛИЗАЦИЯ x=  6.231  y=  5.874  yaw=  +44.7°    6.98 м/с =  25.1 км/ч
ОТСТАВАНИЕ       18 мм        пик 57 мм
возраст измерения     22 мс   пик 41 мс   состояние COASTING
```

**«Отставание»** — это и есть ответ на вопрос «успевает ли одометрия»:
расстояние между тем, где ровер на самом деле, и тем, где его видит
локализация. Истина берётся напрямую из Gazebo и показывается только здесь;
сам рантайм её не видит.

## Как ехать по диагонали

Разгон ограничен сцеплением колёс (μ по умолчанию ≈ 1, то есть около
9.8 м/с²). До 11.11 м/с нужно 6.3 м разгона плюс столько же на торможение,
поэтому вдоль стороны 12 м скорость не успевает набраться.

1. `0` — поднять предел до 12 м/с.
2. Отогнать ровер в угол, например к `(1, 1)`.
3. `A`/`D` — развернуть на 45°, на панели курс `+45°`.
4. Держать `W` через всю диагональ (≈ 17 м).
5. Смотреть в панель: пик скорости и пик отставания.

Реально достижимое в этой арене — **6–7 м/с (22–26 км/ч)**. Четыре заезда,
включая диагональные, выше не дали: ровер почти всё время либо разгоняется,
либо тормозит. 40 км/ч здесь можно только «коснуться», не удержать.

Если нужен настоящий 40 км/ч, выбор один из трёх:

- увеличить сцепление колёс (`mu` в модели ровера): при μ ≈ 3 разгон ~3 g и
  11.11 м/с набирается за 2 м;
- удлинить арену;
- принять «touch-and-go» и мерить только в точке пика.

## Переворот и нижний маркер

Ровер несёт **две** метки: `id 0` сверху и `id 1` снизу, напечатанная
«вверх ногами» (`R_base_tag = diag(1,-1,-1)`). Когда ровер лежит на спине,
два разворота взаимно сокращаются, и потолочная камера видит нижнюю метку
нормально читаемой.

Рантайм это учитывает: `placement` из калибровки говорит, какая метка что
означает, поэтому `id 1` сверху = ровер перевёрнут. Проверено в симуляции:
перевёрнутый ровер в точке (6.0, 6.0) определяется по нижней метке с
ошибкой **9 мм**, высота базы 0.225 м — ровно столько, сколько показал сам
Gazebo после переворота.

Это сильнее, чем просто разрешить гейту принимать «примерно горизонтальную»
позу в любую сторону: у каждого `id` остаётся ровно один ожидаемый знак,
поэтому зеркальная ветвь PnP по-прежнему отбрасывается.

Фильтр при этом знает, что обе метки — **один и тот же** ровер: список
`tags` из калибровки задаёт набор `id`, которые трек считает своими. Без
этого замок личности принимал `id 1` за чужой объект и отбрасывал каждое
измерение от единственной видимой метки — трек уходил в `LOST` и не
возвращался. Чужой `id`, которого нет в калибровке, по-прежнему трек не
забирает.

Попробовать: разгонитесь и воткнитесь в барьер на 6–7 м/с, либо переверните
принудительно — в отдельном терминале

```bash
source /opt/ros/jazzy/setup.bash
.venv/bin/python -c "
import math
from gz.transport13 import Node
from gz.msgs10.pose_pb2 import Pose
from gz.msgs10.boolean_pb2 import Boolean
q=Pose(); q.name='tag_rover'; q.position.x=6; q.position.y=6; q.position.z=0.5
q.orientation.x=1.0; q.orientation.w=0.0
print(Node().request('/world/mocap_arena/set_pose', q, Pose, Boolean, 3000))"
```

Затем `R` в консоли вернёт его на колёса.

## Что смотреть

| Где | На что |
|---|---|
| Консоль | **отставание** в мм и его пик; возраст измерения; состояние |
| 3D | как коробка оценки идёт за ровером; синие точки лидара на нём |
| 3D | полоса `x < 1 м`: там камеры теряют метку, состояние уходит в `REACQUIRING`, коробка краснеет |
| Превью камер | какие камеры реально видят метку на скорости |

Ожидаемое: при 4–8 м/с отставание 21–26 мм (медиана), возраст 22 мс,
состояние `COASTING`. Возраст 22 мс при 7 м/с — это 154 мм пути, а
отставание 21 мм: разницу съедает прогноз фильтра.

## Остановить всё

```bash
scripts/stop.sh
```

Убивает Gazebo и воркеры репозитория вместе с осиротевшими детьми.
`scripts/stop.sh --dry-run` сначала покажет, кого именно.

## Если что-то не поднимается

| Симптом | Причина |
|---|---|
| `Арена уже запущена` | не закрыт прошлый Gazebo → `scripts/stop.sh` |
| `localization runtime already running` | остался прошлый рантайм → `scripts/stop.sh` |
| `run image calibration first` | подан `config/cameras.json` вместо экспортированного из мира |
| В консоли `ЛОКАЛИЗАЦИЯ не подключено` | рантайм не поднялся или другой порт → сверьте `--port` и `--status-url` |
| Ровер не едет быстрее 1 м/с | запущен штатный мир, а не `/tmp/arena_fast.sdf` |
