# Промпт 12 — Панель настройки

> Фаза SIMULATION. Все работы и критерии этого этапа выполняются на Gazebo,
> синтетических данных и replay. Драйверы IMX296/libcamera, udev, реальные камеры,
> сеть узлов захвата и аппаратный trigger — только фаза HARDWARE после S15.
> Общие интерфейсы и поля конфигурации допустимы; отсутствие оборудования
> не блокирует этап и не требует спрашивать пользователя о подключении камер.


Сначала выполни инструкции из `docs/localization_plan/prompts/00_context.md`.
Прочитай результаты предыдущего S-этапа в STATUS.md и используй существующие интерфейсы.

Реализуй backend и UI для registry, камер/линз, intrinsics/extrinsics,
синхронизации, детекторов, фильтров и частот. Используй capabilities sim/replay адаптера: неподдерживаемый hardware trigger нельзя включить зелёной галочкой.
Для sim показывай topic/stream ID. Поля CSI и udev оставь как будущие
возможности со статусом «Доступно на этапе подключения оборудования».

Общее значение мм объектива с per-camera override, рассчитанное покрытие,
совместимость K/D с режимом, raw/undistorted preview. Мастера калибровки
используют реализованные сервисы, progress/cancel/report и независимую проверку.
Редактирование конфигурации staged, validate/apply/rollback атомарные.
Показывай какие операции требуют перезапуска захвата, повторной калибровки
или сброса фильтра. Не хранить черновик только в браузере без защиты от потери.

Web-процесс без root, backend validation upload/schema, localhost по умолчанию,
никаких произвольных команд shell из браузера. E2E: привязка→импорт→калибровка→
применение→откат; отказ одной камеры и устаревший config revision.
Критерий: настройки действительно доходят до узлов, есть ack и error state,
а не только формы с локальным state.

В конце обнови STATUS.md и дай команды воспроизведения результата.
