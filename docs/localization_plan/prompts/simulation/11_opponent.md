# Промпт 11 — Второй ровер ≥10 Гц

> Фаза SIMULATION. Все работы и критерии этого этапа выполняются на Gazebo,
> синтетических данных и replay. Драйверы IMX296/libcamera, udev, реальные камеры,
> сеть узлов захвата и аппаратный trigger — только фаза HARDWARE после S15.
> Общие интерфейсы и поля конфигурации допустимы; отсутствие оборудования
> не блокирует этап и не требует спрашивать пользователя о подключении камер.


Сначала выполни инструкции из `docs/localization_plan/prompts/00_context.md`.
Прочитай результаты предыдущего S-этапа в STATUS.md и используй существующие интерфейсы.

Подключи обученный детектор к общему camera stream. Сохраняй mapping между
исходным кадром, letterbox/resize/ROI и детекцией. Проецируй опорную точку с
учётом высоты и её неопределённости; центр bbox на плоскости пола не считать
точным центром корпуса. Сравни bbox baseline с segmentation/keypoints.

Отделяй второй ровер от своего по положению/проекции AprilTag и совместной
ассоциации с неопределённостью; при скрытой метке поддерживай identity history,
а не правило «все без видимого тега — противник». Ассоциация по времени и
геометрии между камерами, один объект не создаёт несколько независимых треков.

Фильтр XY/velocity и публикация ≥10 Гц, по умолчанию 15. ROI по прогнозу плюс
периодический полный поиск для восстановления; scheduler не должен голодать
по отдельным камерам. Yaw только при наблюдаемости, отдельно флаг 180° ambiguity.
Проверки: сближение, crossing, occlusion, швы, все стили/свет, загрузка GPU.
Критерий: частоты и age измерены, ID switches подсчитаны, LOST не выдаётся за
достоверное слежение.

В конце обнови STATUS.md и дай команды воспроизведения результата.

точку и triangulation доступных соответствий. Не триангулируй произвольные
bbox centers. Размер соперника неизвестен вне конкретного профиля — включи
ошибку габаритов. Threshold выбирай по валидации, gating не лечит все false positives.
