# H02 — Захват и постоянная привязка

> Фаза HARDWARE: выполнять только после SIM_ACCEPTED и отдельного запуска
> аппаратной фазы пользователем. Не входит в очередь симуляционных работ.

Сначала выполни инструкции из `docs/localization_plan/prompts/00_context.md`.
Прочитай результаты предыдущего H-этапа в STATUS.md; используй готовое ядро из SIM-фазы.

Сделай camera registry и libcamera capture adapter для выбранных CSI камер,
с возможностью удалённых узлов. Логический ID связывай с node_id, camera ID,
портом/media graph и паспортом модуля. Не используй случайный /dev/videoN.
Интерфейс обязан различать hardware identity и port-based binding.

Добавь enumeration, capabilities, preview, ручное назначение camera_1..6,
проверку уникальности, reconnect/backoff и bounded queues. Изменение режима
должно инвалидировать несовместимую калибровку. Сохраняй capture metadata.
Для действительно доступных V4L2/USB endpoints реализуй генератор udev rules
по фактическим атрибутам и правильному capture node; CSI/libcamera не подменяй UVC.
Вывод правил — файл, dry-run и инструкция; web backend не получает root.

Проверь перестановку индексов, два одинаковых устройства без serial, замену
камеры, отключение одного узла. Без аппаратуры используй replay fixtures с
честным статусом UNVERIFIED. Критерий: остальные камеры продолжают работу,
одна камера не захватывается двумя процессами, логический ID не перепрыгивает.

В конце обнови STATUS.md и дай команды воспроизведения результата.

В этом этапе подготовь и установи требуемые драйверы IMX296 на выбранных узлах
по проверенным инструкциям конкретного SKU/ОС, фиксируя версии и откат.
Не переносить эти зависимости в обязательные зависимости запуска sim/replay.
