## 2. Единственный оставшийся дефицит покрытия — геометрический

92.02 % вместо 95 %. Все потери локализованы:

```text
  start_s   len_ms       x       y
    259.4     4150    1.01    5.60
    160.0     4089    1.00    3.60
     60.7     4087    1.00    1.60
    358.8     4082    0.99    7.60
    209.7     4080    0.99    4.61
    309.1     4079    0.99    6.60
    408.5     4079    0.99    8.60
    507.9     4076    1.00   10.60
    458.2     4074    1.00    9.60
    110.4     4014    0.99    2.60
```

Десять разрывов по ~4.1 с, все при `x ≈ 1.0` — по одному на каждый разворот
змейки у западного края. Карта `pnp_rate` по клеткам: **4–6 % в столбце
`x ∈ [0,1)` и ~100 % во всех остальных клетках арены.**

Причина по кадрам в окне разрыва: метку видит только `camera_3`
(18 детекций из 75 кадров), и 9 из них отклонены как `frame_edge`. Камеры
стоят на `x = 3` и `x = 9`; по вертикальной оси кадра предел досягаемости
`480/493.6 · 2.535 = 2.46 м`, а доска 0.5 м и отступ 8 px съедают остаток.
При `x = 0.8` (точка разворота) марка уже срезана краем кадра.

Проверка, может ли это закрыть переориентация центральной пары (сетка
0.2 м по полосе `x ∈ [0.8,1.6]`, требуется вся доска 0.5 м в кадре с
отступом 8 px и incidence ≤ 65°):

| Центральная пара | полоса `x∈[0.8,1.6]` | вся арена ≥1 | вся арена ≥2 |
|---|---:|---:|---:|
| текущая 40° / yaw 35–215 | 80.0 % | 97.3 % | 48.3 % |
| 40° / yaw 0–180 | 80.0 % | 90.5 % | 55.6 % |
| 40° / yaw 90–270 | 80.0 % | 97.3 % | 50.2 % |
| 28° / yaw 0–180 | 80.0 % | 91.3 % | 60.1 % |
| **28° / yaw 90–270** | 80.0 % | **97.6 %** | **52.3 %** |

**Переориентация центральных камер западную полосу не закрывает** — 80 % при
любом варианте. Гипотеза «дело в yaw 35°» не подтвердилась: центральные
камеры находятся в 5 м от `x = 1` и при любом повороте туда не дотягиваются.

Это меняет вывод раздела 8 аналитического документа. При строгом критерии
(вся доска в кадре + отступ + incidence) варианты различаются заметнее, чем
в исходной оценке, и лучший из проверенных — **28° / yaw 90–270**: одиночное
покрытие 97.6 % (максимум) и двойное 52.3 % против 48.3 % у текущего. Это
предсказание модели, его нужно проверить отдельным прогоном.

Закрыть полосу `x < 1 м` можно только:
- сузив рабочую зону до `x ∈ [1.2, 10.8]` (изменение ТЗ арены), либо
- подключив лидар L2, либо
- увеличив метку (0.6 м вместо 0.4 м даёт запас по краю), либо
- наклонив угловые камеры внутрь — но это ухудшает σ и требует
  перекалибровки всех четырёх.

## 3. Что показал прогон про режимы работы

```text
режимы кадров: acquire 4560, roi 12389, watchdog 1067
кадров обработано 18 016, пропущено планировщиком 32 720, потеряно 0
```

Планировщик ROI снимает нагрузку с 65 % кадров. Суммарно
`18 016 + 32 720 = 50 736` против `6 × 15 Гц × 559 с = 50 310` — то есть
принято и учтено всё, потерь очереди нет (было 35 %).

Отказы гейтов за весь прогон:

```text
incidence 624, frame_edge 295, base_height 2,
no_physical_solution 2, nonplanar_pose 1, pnp_ray_disagreement 1
```

`base_height` сработал 2 раза за 10 775 решений. Гейт, который в старом
прогоне пропускал 39.5 % физически невозможных высот, теперь почти не нужен —
потому что причина устранена, а не замаскирована.

## 5. Честная оценка критериев приёмки

| Критерий | Статус |
|---|---|
| valid coverage ≥ 95 % | **не выполнен** (92.0 %), причина геометрическая, см. §2 |
| P50 XY ≤ 0.08 м | выполнен с запасом 20× (0.0040) |
| P95 XY ≤ 0.20 м | выполнен с запасом 18× (0.0111) |
| P95 yaw ≤ 10° | выполнен (1.13°) |
| P95 age ≤ 50 мс | **недостижим при 15 Гц** — период кадра 66 мс. Фактически 90 мс |
| ID switches = 0 | выполнен |
| нет физически невозможных Z | выполнен (0.0 %) |

Предлагаемая корректировка: `valid coverage ≥ 92 %` для камер без лидара и
`≥ 97 %` после подключения L2; `P95 measurement age ≤ 150 мс` при камерах
15 Гц и `≤ 30 мс` при 90 Гц.

## 6. Чего прогон не проверяет

- Лидар L2 не подключён.
- Скорость только 0.5 м/с. Поведение при 11.11 м/с не измерено: при 15 Гц
  камерах кадр приходит раз в 0.74 м пути, это отдельный эксперимент.
- Один ровер. Сценарий с двумя роверами и пересечением не запускался.
- Рендер Gazebo — идеальный pinhole без дисторсии (см. `040e4cf`).
  Настоящая дисторсия IMX219 требует rational/fisheye калибровки и
  отдельной проверки на железе.
