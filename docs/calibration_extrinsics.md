# Взаимное положение шести камер по ChArUco-полотну

Цель: позы всех шести камер в системе арены (X, Y по полу, Z вверх) за один
сеанс по напольному полотну 12×3 м. Результат: `runtime_cameras.json` того же
формата, что `config/mocap_arena_imx219/`, и отчёт с точностью по каждой камере.

| | |
|---|---|
| запуск | `scripts/hardware/calibrate_extrinsics.sh start` → страница http://localhost:8090 |
| без железа | `scripts/hardware/calibrate_extrinsics.sh demo` |
| пересчёт по сохранённой сессии | `scripts/hardware/calibrate_extrinsics.sh solve artifacts/calibration/<сессия>` |
| код | `scripts/calibration_station.py` (+ `.html`), `localization_contracts/charuco_calibration.py`, `scripts/solve_extrinsics.py` |

## Что нужно до начала

1. **Полотно** из `assets/charuco_strip/` (печать — `docs/charuco_strip.md`):
   30×6 клеток по 375 мм, маркеры 280 мм, `DICT_5X5_250`, белая кайма 375 мм,
   лист 12×3 м. Лежит ровно, без складок; на глянце не должно быть бликов от прожекторов.
2. **Внутренние параметры камер** (K, D при 1640×1232) — по
   [calibration_intrinsics.md](calibration_intrinsics.md). Станция сама берёт их из
   `intrinsics/<камера>/` той же сессии (`--session`) или из `--intrinsics <каталог>`.
   Без них подставляются K, D из базового конфига: это идеальный объектив из
   симуляции, не калибровка. Страница помечает такие камеры красным в столбце «K, D».
   Позы при этом получатся, но с ошибкой.
3. **Узлы обновлены.** Поток полных кадров по таймеру со сдвигом фазы и серый
   JPEG появились в `pi_cam/camera_node.py` вместе с этой станцией. После `git pull`
   на каждом Pi:
   ```bash
   sudo scripts/hardware/setup_cm4_node.sh N
   ```
   ```bash
   sudo systemctl restart camera_node
   ```
   Старый узел станция распознаёт и пишет в журнал «узел не знает поток по таймеру».
4. **Свет и экспозиция.** Маркер должен читаться: при `exposure_us 800` в тёмном зале
   кадр почти чёрный. На время калибровки — свет арены или `exposure_us` 2000–4000 в
   `/etc/mocap-rover/node_config.json` (полотно неподвижно, смаз не страшен).
5. PTP желателен: по нему узлы держат сдвиг кадров между собой. Без PTP сдвиг
   приблизительный, на калибровку это не влияет.

## Кадры, частота и сдвиг

- Каждая камера шлёт **полный кадр 1640×1232** в виде серого JPEG (q90). Узел CM4
  читает сырой Bayer, поэтому перед JPEG переводит мозаику в яркость (`gray`):
  мозаику JPEG не переносит.
- **Частота 20 Гц или 10 Гц.** В режиме «авто» станция стартует с 20 Гц и
  переходит на 10 Гц, если канал загружен больше 70 % от 940 Мбит/с, если узел или
  ноутбук сбрасывают больше 10 % кадров или если камера отдаёт меньше 75 % заданной
  частоты (оба условия — два замера подряд). Причина пишется в шапке страницы.
  Можно зафиксировать вручную: переключатель «20 Гц / 10 Гц» или `--rate 10`.
- **Сдвиг.** Камера k из N получает фазу `k · период / N` на общей шкале времени:
  при 20 Гц кадры шести камер идут через 8.3 мс, при 10 Гц — через 16.7 мс. На
  коммутатор не приходят шесть кадров одновременно, буферы не переполняются.
  Фаза каждой камеры видна на её карточке.
- Объём: в демо кадр ~225 КБ, это ~36 Мбит/с на камеру при 20 Гц и ~220 Мбит/с на
  шесть. Реальный кадр с шумом сенсора крупнее; сколько выйдет на стенде,
  покажет шапка страницы. **На железе не измерялось**, включая нагрузку CM4 на
  перевод в яркость + JPEG при 20 Гц. Если узел не успевает, «авто» уйдёт на 10 Гц.

## Порядок работы

1. Запустить станцию и открыть страницу:
   ```bash
   scripts/hardware/calibrate_extrinsics.sh start
   ```
   Продолжить сессию, где уже есть внутренняя калибровка:
   ```bash
   scripts/hardware/calibrate_extrinsics.sh start --session artifacts/calibration/<сессия>
   ```
2. Вкладка **«Взаимное положение»**. Шесть карточек: живой кадр, зелёные точки —
   найденные углы полотна, число углов и маркеров, к/с (факт / задано), фаза,
   Мбит/с, задержка, возраст кадра, частота сенсора, сброшенные кадры, температура,
   смещение PTP. Число углов: зелёное ≥ 65, жёлтое ≥ 20, красное < 20.
3. **Положение 0 (опорное).** Положить полотно посередине арены, измерить рулеткой
   и ввести:
   - `x0, y0` — точка арены, где лежит **угол листа (с каймой) со стороны маркера
     ID 0**, то есть левый верхний угол печати;
   - `yaw` — поворот длинной стороны относительно оси +X арены. Измерить Y обоих
     концов края: `yaw = atan((y_конец − y_начало) / 12 м)`. Верхний край печати
     смотрит в сторону +Y.

   Поставить галочку «измерено» и нажать **«Снять положение»**. Станция усредняет
   последние 4 кадра каждой камеры, сохраняет PNG и считает углы.
   Это положение задаёт систему арены: его точность — точность всей калибровки
   в целом (сдвиг на 1 см сдвигает все камеры на 1 см).
4. **Положения 1, 2, …** Сдвинуть полотно так, чтобы его увидели камеры, которые в
   положении 0 видели мало углов. Для раскладки `mocap_arena_imx219` (камеры в
   рядах Y = 2, 6, 10) хватает трёх: верх листа на Y ≈ 7.5 (опорное), 4.6 и 10.4 м.
   Эти положения мерить не обязательно: снимать **без** галочки, станция решит
   их сама. Условие — в каждом положении хотя бы одна камера, уже привязанная
   через предыдущие (на рядах это средний ряд, камеры 3 и 4).
5. **«Решить взаимное положение».** Решение совместное: позы всех камер и
   нерешённые положения полотна подбираются вместе, минимизируется ошибка
   репроекции всех углов через fisheye-модель (функция потерь Huber, 1 px).
   Начальное приближение — PnP по одному кадру на камеру.
6. Таблица результата: X, Y, Z, наклон оптической оси от вертикали, курс оси x
   изображения, число углов, ошибка репроекции P50/P95, σ позиции (по ковариации),
   «разброс» (насколько позы по отдельным положениям расходятся с совместным
   решением), источник K, D. Ниже — вид арены сверху (камеры, точка пола в центре
   кадра, положения полотна, ★ = измеренное) и матрица расстояний между камерами.
   Внизу страницы — журнал и путь сессии.

Положение можно убрать кнопкой «убрать» (снимки остаются на диске, из решения
выпадают) и снять заново.

## Что считать хорошим результатом

| | норма | что делать, если хуже |
|---|---|---|
| ошибка репроекции P95 | ≤ 1.5 px | проверить K, D камеры (столбец «K, D»), блики, складки полотна |
| σ позиции | ≤ 3 мм | больше углов: ещё одно положение ближе к камере |
| разброс | ≤ 10–20 мм | большой разброс у камеры, которая видит полотно краем (< 20 углов), — норма; у камеры с ≥ 65 углами — признак неверных K, D |
| «не решена» | нет | камера не видит ни одного положения, общего с решёнными: добавить положение под ней |

Демо (синтетические кадры через JPEG, известные позы с ошибками монтажа):
ошибка репроекции P95 0.85 px, позиции камер 0.9–1.6 мм, повороты 0.02–0.06°
против эталона; свободные положения полотна найдены с точностью ~1 мм.

## Файлы сессии

```
artifacts/calibration/<дата_время>/
  extrinsics/manifest.json            положения: x0, y0, yaw, измерено/нет, углы по камерам
  extrinsics/placement_N/camera_K.png снимки 1640×1232 (среднее 4 кадров)
  extrinsics/runtime_cameras.json     ← результат: базовый конфиг + позы + K, D, role image_calibrated
  extrinsics/calibration_report.json  всё из таблицы + положения полотна + источники K, D
```

Каталог `artifacts/` в git не попадает. Использовать результат:

```bash
CAM_CONFIG=artifacts/calibration/<сессия>/extrinsics/runtime_cameras.json scripts/hardware/run_hardware.sh record run_01 60
```

Пересчитать решение без станции (например, после новой внутренней калибровки):

```bash
scripts/hardware/calibrate_extrinsics.sh solve artifacts/calibration/<сессия>
```

```bash
scripts/hardware/calibrate_extrinsics.sh solve artifacts/calibration/<сессия> --intrinsics artifacts/calibration/<другая>/intrinsics
```

## Параметры станции

`.venv/bin/python scripts/calibration_station.py --help`. Основные: `--nodes`,
`--port` (8090), `--session`, `--base-config` (по умолчанию
`config/mocap_arena_imx219/runtime_cameras.json`; имена камер в нём должны
совпадать с `camera_id` узлов), `--intrinsics`, `--rate auto|20|10`,
`--link-mbit 940`, `--max-load 0.7`.

## Чего нет

- Лидар к арене станция не привязывает (промпт 05, п. 3).
- Высота полотна считается нулевой (пол — плоскость Z = 0); неровный пол даёт
  ошибку того же порядка.
- На реальном стенде станция не запускалась: проверено на демо с шестью узлами
  `camera_node` в одном процессе и тестами.
